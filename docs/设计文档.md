# 刀剑乱舞ぱずぎり MAA 设计文档

状态：总体设计稿；客户端基础布局、作战策略编辑器与 JSON 存储已实现，任务策略选择与单步战斗动作已接入，实机交互验收待完成

最近更新：2026-10-20

## 项目目标

构建一个基于 MaaFramework 的《刀剑乱舞ぱずぎり》自动化项目，优先通过 MuMu 模拟器运行，只适配游戏官方日文界面。项目使用 Maa 标准项目结构，并将游戏流程、视觉识别、连线棋盘建模和策略计算分层，便于先搭建框架，再用实际画面验证实现选择。

## 已确认的范围

- 使用 MaaFramework 与 Project Interface V2。
- 首选 MuMu 模拟器及 ADB 控制。
- 只适配官方日文界面。
- 运行界面采用基于 MFAAvalonia 上游源码轻度定制的专属客户端，在独立 GitHub 仓库维护和发布；MAP 业务项目在打包时下载客户端产物。
- 首页保留经典三列卡片布局：左侧任务列表，中间任务设置与任务说明，右侧日志；首页不提供实时视图。
- 首批任务为“领取奖励”和“常驻作战”，优先开发常驻作战。“常驻作战”与 MATR 的任务命名保持一致，当前先支持主线关卡。“领取奖励”按一键领取全部支持奖励设计，暂缓开发。
- 常驻作战的任务设置采用“常规设置／高级设置”两个页面；常规设置提供策略选择，侧边栏提供独立“作战策略”页面。自定义策略由用户命名，每个策略保存为独立文件，并提供始终可选的默认策略。
- 棋盘是连线形消除玩法，棋盘及棋子位置不固定，棋子可能有不同尺寸，并存在可点击使用的炸弹等道具。
- 先验证基于颜色与局部模板的 OpenCV 离线识别原型，YOLO 保留为备选。当前识别范围为四种颜色的饿鬼与一至三级炸弹，详见[饿鬼与炸弹视觉识别设计](superpowers/specs/2026-10-16-board-vision-design.md)。
- 后续可能为 MFAAvalonia 增加侧边栏仓库入口或其他游戏专属功能。

## 项目框架与开发工具

### create-maa-project

使用 [create-maa-project](https://github.com/Windsland52/create-maa-project) 作为本项目唯一的框架生成与维护工具。为棋盘重建、识别后处理和策略计算预留 Python 自定义逻辑，创建时选择 `agent` 项目类型，并启用 ADB 控制目标。开发工具和 GitHub 工作流按实际维护需要选择。

该工具负责生成及维护项目结构、Project Interface、资源目录和开发工具配置；业务 Pipeline、识别模型、策略代码仍由本项目实现。它也提供 MaaFramework 与 MFAAvalonia 运行时资产同步能力。生成后使用 `--doctor` 检查项目状态；构建、打包和发布由生成项目提供的开发工具及工作流承担。

### Everything-Maa

将 [Everything-Maa](https://github.com/KhazixW2/Everything-Maa) 作为 Codex 开发辅助技能，参考 Maa 项目、Pipeline、Agent 和调试工作流。它与 create-maa-project 的创建技能可以配合使用，但项目文件的生成和维护仍交由 create-maa-project，避免两套工具重复管理同一批文件。

### MaaPracticeBoilerplate

[MaaPracticeBoilerplate](https://github.com/MaaXYZ/MaaPracticeBoilerplate) 作为 Maa 标准结构、Project Interface V2 和 MFAAvalonia 集成方式的参考资料，不再作为第二套项目生成器。这样保留标准 Maa 约定，同时由 create-maa-project 统一维护项目状态和受管文件。

## M9A 与界面扩展参考

[M9A](https://github.com/MAA1999/M9A) 的公开资源接口包含 GitHub 仓库地址、Agent 配置和多个资源包；其说明和发布包也展示了 MFAAvalonia、MXU 等通用客户端的使用方式。它适合作为大型 Maa 资源项目的组织参考。已确认 M9A 没有侧边栏仓库入口，因此不能把它当作该界面功能的现成范例。

### 首页布局

首页保持三列卡片形式：

| 位置 | 内容 | 已确认的要求 |
| --- | --- | --- |
| 左列 | 任务列表 | 首批任务为“领取奖励”和“常驻作战”，后续可追加“角色培养”等任务 |
| 中列上方 | 任务设置 | 选中任务后显示对应设置，优先复用 MFAA 已有控件 |
| 中列下方 | 任务说明 | 展示任务用途、使用要求与选项说明 |
| 右列 | 日志 | 首页不放实时视图，将右列用于日志 |

竖屏游戏画面不适合放入当前首页布局，因此首页不提供实时视图。保留上游侧边栏总控台的实时画面，以及设置页中的实时视图开关和刷新率；这些共享设置继续供总控台使用，首页卡片不再随开关出现。首轮实现保留上游现有的等宽三列与中间两卡片高度比例，窗口初始尺寸等其他数值后续再定，不直接沿用 MATR 的具体数值。

在所选客户端版本支持的范围内，使用 `config/config.template.json` 设置新安装的初始窗口尺寸。当前已增加 `resource/base/mfa_layout.json`，定义三列四卡片及日志整列布局；专属客户端同时从首页移除实时视图控件及可见性同步，不使用共享实时视图开关来隐藏首页卡片，以保留总控台的开关行为。

总控台实时画面卡片默认尺寸已从横向的 360×240 调整为竖向的 240×420，保留现有缩放、全屏查看和卡片操作。该尺寸用于客户端画面展示，不作为游戏截图分辨率、识别 ROI 或触控坐标的依据。

### 首批任务与常驻作战设置

“领取奖励”按一次执行领取全部支持奖励设计，不提供逐项选择奖励的设置；具体支持哪些奖励待后续确定。当前优先开发“常驻作战”。未实现的领取奖励任务是否先显示在列表中，留待实现前确认。

常驻作战的任务设置卡片采用“常规设置／高级设置”两个页面。常规设置放置章节、关卡、部队、资源补充与策略选择等高频选项；高级设置呈现任务资源声明的高级选项。复杂策略在独立页面编辑，任务设置卡片通过下拉框选择策略。卡死恢复不提供用户开关，默认启用。

常规设置已确认需要支持以下功能：

| 功能 | 当前 UI 设计依据 | 尚待确定的内容 |
| --- | --- | --- |
| 重复次数 | 使用任务的 `repeatable` 与 `repeat_count`，复用 MFAA 原生次数控件，不另建重复次数 `input` 选项 | 初始默认次数 |
| 选择章节 | 使用任务选项中的单选下拉框 | 章节清单与默认项 |
| 选择关卡 | 使用任务选项中的单选下拉框 | 关卡清单，以及与章节选择的关联呈现 |
| 选择部队 | 使用任务选项中的单选下拉框 | 部队可选项与默认项 |
| 使用体力药 | 提供使用开关，沿用 MFAA 滑块形式 | 是否设置使用上限、数量含义和药品选择 |
| 使用碎玉换体 | 提供使用开关，沿用 MFAA 滑块形式 | 是否设置兑换上限、次数含义和默认值 |
| 碎玉续关 | 提供独立滑块开关，与“使用碎玉换体”分别控制 | 是否设置续关上限、次数含义和默认值 |
| 作战策略 | 单选下拉框，包含“默认策略”和用户保存的策略名称；初始选择默认策略 | 任务侧接入待实现；找不到目标策略时回退默认策略 |

`repeatable` 控制是否展示任务自带的次数控件，`repeat_count` 提供初始次数；用户修改后由客户端保存任务配置。具体重复执行与一次通关的边界在后续流程设计中确认。

指定材料刷取暂不实现，也不作为当前必填设置。角色培养属于未来可追加任务，本轮不展开其设置。

### 独立策略编辑与保存

侧边栏提供“作战策略”入口。左侧为策略列表，提供新建、复制、重命名；右侧纵向堆叠可命名、独立展开、拖动展示排序的阶段卡片。阶段标题右键菜单提供重命名、复制、删除、设为初始阶段。末张卡片下方放加号，底部固定工具栏提供保存、删除整份策略、全部展开和折叠，右侧顶部不加工具栏，不自动生成中文摘要。

用户通过图形界面编辑策略并自行取名，每份策略独立保存到统一配置目录的 `strategies/<稳定标识>.json`，当前为安装目录下的 `config/strategies/`。格式版本为 1，采用 UTF-8、缩进与 snake_case；策略、阶段、转变使用稳定标识，名称和展示顺序不影响引用。任务下拉选择后续接入，同一策略可供多个任务配置选用。

“默认策略”始终保留，采用以下行为：

- 奥义可用即释放。
- 乱舞不保留颜色，消除所有颜色的饿鬼。
- 一个“全程作战”阶段，奥义优先、炸弹其次、普通连线最后；奥义三个位置均启用且无额外前置，只使用三级炸弹，普通连线不启用颜色优先级。乱舞允许奥义与炸弹。

默认策略只读，可复制为自定义策略。删除策略不检查任务引用，后续执行端找不到目标时回退默认策略；损坏与未来版本文件明确报错。任务启动时读取快照，之后保存下次启动生效。切换策略、离页和关闭窗口有保存、放弃、取消弹窗，保存失败保留原文件与草稿。保存前校验，使用同目录临时文件替换，缺少必备配置不会悄悄补成默认值。

策略编辑器是客户端的主要专属定制部分，首页继续沿用经典 MFAA 三列卡片布局。

客户端已实现侧边栏入口、阶段与递归条件编辑、策略文件保存重载及未保存保护，并有自动化测试覆盖。格式与完整示例见客户端仓库的 `docs/zh/作战策略JSON格式.md` 和 `docs/examples/combat-strategy-v1.json`。真实窗口的拖动、弹窗和尺寸仍待交互验收。MAP 的任务选择、血量识别和 Python 战斗执行尚未接入，本轮只建立可消费的策略文件契约。

### 战斗策略的表达与设计边界

策略面向稳定、较高收益的重复刷关，根据当前随机堆叠棋盘作出行动决策。不同关卡可以使用不同策略配置，但不能把策略设计成固定坐标或固定连线路径的作业回放。

策略采用用户自行划分的阶段，每阶段配置行动与转变条件。至少保留一个阶段，全程使用同一套策略也可以；初始阶段独立指定，展示顺序不决定执行顺序，可跳转到任意阶段并形成循环。奥义前置和阶段转变使用可嵌套的“全部满足／任一满足”条件组，数值比较和状态期望表达否定，不要求用户写逻辑代码。

下列交互与约束已在讨论中明确：

- 乱舞最多保留一种颜色；分别提供允许奥义、允许炸弹两个开关，开启后仍继承本阶段的许可与前置。
- 奥义与炸弹可拖动调整类别优先级，普通连线固定最后，普通操作与乱舞同时生效。炸弹仅勾选允许使用的一至三级，优先可用的高等级；四级自动爆炸按过渡处理。
- 奥义按固定位置 1、2、3 勾选并拖动排序，自身就绪内置；额外前置不满足则跳过检查下一位置。奥义条件仅提供“奥义已就绪”和“奥义未就绪”，位置可多选且所选位置都需满足；任一关系由条件组组合，不提供已释放条件。
- 条件支持本场和本阶段成功普通连线手数、敌我血量百分比、奥义已就绪或未就绪、乱舞状态。血量由后续 OCR 读取，百分比须有可靠的当前与最大值，未知状态不能因取反变为满足。不兼容旧的血量数值和奥义已释放条件文件。
- 本场手数与阶段手数同时保留；进入阶段重置阶段手数，本场手数不清零。炸弹、奥义和乱舞连线不计入普通连线手数，只有成功普通连线才计数。
- 普通连线可为零至四种颜色编号设置优先级；存在至少七连的候选时，先限定到达标颜色再按已编号的颜色排序，否则在所有候选颜色中排序。未编号的颜色优先级相同，按连线长度选择。编辑器通过 `color_priority_count` 保存已编号数量，旧策略缺少该字段时按四色均已编号处理。首版不开放其他普通连线偏好。
- 多条转变按顺序首命中，先转变再行动；执行端每次只执行一步，确认新状态后重判，并防止没有行动或新观察的循环跳转。运行计数与卡片折叠状态不写入策略。
- 删除唯一阶段或当前初始阶段需先保留或另设初始阶段；删除被其他阶段引用的阶段时提示修正引用。复制策略重映射所有内部标识与目标，复制单阶段保留其他目标并将自身目标映射到副本。
- 不向用户开放识别阈值或滑动速度；当前策略设计不纳入绘马配置。
- 不要求普通用户使用逐手测试、记手校准或作业录制等辅助工具。普通连线计数由执行逻辑维护，运行状态在 UI 中展示到什么程度后续再定。

已知策略示例可用于后续核对编辑器的表达能力：开战后普通连线、保留炸弹并尽量合成三级；达到指定手数并等待 Boss 特殊技能结算后，点炸弹并依照角色前置条件释放奥义；若尚未进入乱舞，则继续普通连线和使用炸弹。乱舞期间保留红色、不使用炸弹与奥义；结束后先普通连线消除红色，再循环点炸弹、释放奥义和普通连线，直到战斗结束。该示例是用户自定义策略的使用场景，不作为所有策略的固定阶段，也不覆盖默认策略。

玩法规则、用户实机观察与外部资料的证据边界见[玩法与近期活动调研](research/2026-10-17-gameplay-and-event-research.md)。该文档是研究依据，其中候选建议不等同于已确认的 UI 方案；本节记录当前设计范围。

### MATR 的可借鉴经验

2026-10-17 对 `D:/Claude_Workspace/MATR` 进行了只读源码核对，重点包括 `assets/interface.json`、`assets/resource/mfa_layout.json`、`_src/MFAAvalonia/Helper/TaskOptionGenerator.cs`、`_src/MFAAvalonia/Views/Pages/TaskQueueView.axaml.cs` 和 `docs/upstream-customizations.md`。以下是参考经验，不代表整体采用 MATR 的配置与定制层。

- **先区分任务属性与业务选项**：MATR 的常驻作战通过 `repeatable`、`repeat_count` 使用任务自带的次数控件，地图、部队等业务设置通过 `option` 列表声明；避免为已有原生能力再创建一套选项。
- **任务设置与说明分别呈现**：任务选项按声明组织，说明使用现有说明卡片承载。MAP 沿用经典卡片结构，具体尺寸单独设计。
- **下级选项可以采用不同展示方式**：MATR 默认以齿轮进入设置区的下级页面，也通过 `inline_sub_options: true` 将下级选项直接展示在上级选项下。后者是 MATR 的本地客户端扩展，不能当作 MaaFramework 通用字段或未经核实的 MFAA 上游能力。MAP 若需要相同内联效果，应在自己的轻度定制中核对并实现相应支持。
- **不要整体复制高强度定制**：MATR 还有专属编队预设、工具入口、复选框样式和其他游戏业务。MAP 从 MFAA 上游建立自己的客户端，只按实际需求借鉴局部实现；MATR 的历史兼容字段和游戏业务不能直接搬入 MAP 的 PI V2。
- **客户端定制应有明确记录**：参考 MATR 的上游定制台账，为 MAP 每项保留的 UI 改动记录用途、涉及文件及采用的上游版本，便于之后升级时核对，而不是用旧文件覆盖新上游。
- **隐藏卡片与调整布局分开处理**：MATR 对实时视图卡片单独控制可见性，布局文件则负责卡片位置与尺寸。MAP 的首页去除实时视图时同样需要分别核对这两层行为。

上述经验基于本地源码与定制说明，本轮未启动 MATR 客户端或验证其运行界面。

## 运行架构

### 游戏流程

Pipeline 负责启动游戏、页面导航、进入关卡、等待动画稳定和确认操作结果。Project Interface V2 声明任务、选项和控制器，使 MFAAvalonia 能加载资源并执行任务。识别与策略需要复杂逻辑时，由 Pipeline 调用 Python Agent。

### 棋盘表示与视觉识别

不能将棋盘预设为固定行列或固定格子坐标。每帧棋盘状态至少需要表达：

- 棋盘区域和当前布局。
- 每个棋子或道具的检测框、中心点、类别、尺寸或占位范围及置信度。
- 棋子之间可连线的节点与边，以及当前连线规则所需的状态。
- 炸弹等可点击道具的位置、可用状态和对应点击坐标。
- 当前画面是否处于稳定状态，是否被动画、特效或遮挡影响。

当前先用 OpenCV 的颜色分析与局部模板匹配定位饿鬼和炸弹，由 Agent 输出类别、中心、主体范围、可见证据及不确定信息。眼睛和嘴巴分别提供定位线索，以处理部分遮挡与同色接触。识别结果必须保留实际尺寸，中心估计与候选操作点分开表达。

炸弹共有四级，前三个等级以不同外焰作为主要识别依据，内部 QQ 人不参与等级判别；四级合成后直接爆炸清屏，作为画面过渡处理。当前离线原型已扩展贝壳、石头、箱子、树枝四种障碍物和特殊黑色饿鬼，按实际截图的局部纹理与颜色定位。强化饿鬼保留原颜色，核心与受影响统一为强化状态；新增青铜钟在已核对的固定区域逐帧检查亮暗外观，不推断其作用或点击语义。后续其他木头外观取得样本后再增加细分类别与模板；未识别区域不能直接当成空地或可通过路径。

具体算法、输出约定、样本范围和分阶段验收见[饿鬼与炸弹视觉识别设计](superpowers/specs/2026-10-16-board-vision-design.md)。已实现离线候选识别和诊断输出，使用方法与已知漏检见[原型说明](../training/board-vision/README.md)；传统方法尚未通过独立效果评估。若典型遮挡或粘连反复定位失败，再评估轻量 YOLO 检测模型；不同实现共用对象状态结构。

原始截图可用于模板制作、评估和后续候选模型训练。模板制作与阈值调整使用开发样本，独立评估画面不参与这些工作；评估失败图若用于修订，就转为开发样本并另留新的独立样本。接入自动操作前，还需确认连续画面稳定、触控点、合法连线规则及动作后的状态变化。

### 棋盘重建与策略

Agent 将视觉检测结果转为图结构：节点表示可操作棋子或位置，边表示规则允许的连线关系；节点数据保存类别、大小、占位和道具状态。策略模块只接收已校验的图状态，计算符合游戏规则的连线或道具操作，并输出屏幕坐标和动作序列。

游戏规则、棋子大小如何影响连线、炸弹的触发方式和优先级需通过实际游玩画面或说明确认。在这些规则验证前，不固定具体寻路算法、类别表或炸弹策略。

## 控制与识别

- 通过 ADB 连接 MuMu，验证设备发现、截图、点击和滑动。
- 页面导航先用模板匹配、颜色识别和日文 OCR；只制作官方日文界面的识别资源。
- 每次棋盘动作前获取稳定截图；动作后等待动画结束，再重新识别并校验状态变化。
- 识别结果低置信度、图结构无法校验、页面状态未知或动作结果不符预期时，停止任务并保存日志和截图。

## 实施阶段

1. 评审本设计稿，确认脚手架、GUI 路线和视觉识别与 Agent 的职责边界。
2. 使用 create-maa-project 创建 Agent 项目，选择 ADB 控制，并检查生成的 PI V2、目录和发布工作流。
3. 客户端策略编辑与 JSON 存储已实现；继续接入常驻作战的常规设置、高级设置与任务策略选择，并验证编辑器、MuMu 连接、首页三列布局和总控台实时画面的完整交互。
4. 采集官方日文界面截图，记录页面流程、棋盘结构、棋子大小、消除规则和炸弹交互。
5. 制作饿鬼与炸弹的 OpenCV 离线识别原型，用独立截图核对遮挡、同色接触与炸弹等级，按结果决定实时接入或重评 YOLO 方案。
6. 实现动态棋盘图重建、规则校验和策略计算，再通过 Pipeline 执行动作并确认结果。
7. 建立 UI 仓库的客户端构建与 Release 流程，将其 GitHub 客户端产物下载接入 MAP 打包流程。
8. 验证资源打包、客户端集成和最终发布产物，后续再扩展领取奖励与其他任务。

## 首版验收目标

- create-maa-project 生成的 Maa 标准 Agent 项目可被 MFAAvalonia 正确加载。
- 可在 MuMu 上稳定连接、截图并执行基本触控操作。
- 资源限定为官方日文界面，首页采用左侧任务列表、中间任务设置与说明、右侧日志的三列卡片布局，不显示实时视图。
- 常驻作战采用常规设置与高级设置，提供章节、关卡、部队、体力补充、碎玉续关与策略选择，重复次数复用 MFAA 自带控件；具体默认值与消耗上限按后续确认结果实现。
- 侧边栏提供独立作战策略编辑入口；用户可命名保存自定义策略，每个策略独立存储，并在任务中选择。默认策略始终可选，奥义可用即释放、乱舞不留色，不设置额外自定义条件。
- 识别结果能表达可变棋盘、不同尺寸棋子和可点击道具，并能重建合法连线关系。
- 策略只对校验通过的棋盘状态产生合法操作；低置信度或执行异常时安全停止。
- 发布产物包含 MaaFramework 运行组件、资源、Python Agent 和从独立 UI 仓库 GitHub Release 下载的专属客户端。

## 当前战斗动作流程

- `BattleSession` 每轮重新截图并判断胜负、普通可操作或乱舞；确认战斗可操作后，由观测器读取当前帧棋盘和策略所需指标。已确认乱舞时，轮询休眠由200毫秒缩短至最多20毫秒，使预选点能更快取得下一张独立截图；其他状态保留原轮询间隔。用户观察乱舞松手后消除动画约半秒，因此乱舞最短等待改为500毫秒，然后重新确认状态与两帧同点颜色；普通连线仍等待一秒。500毫秒为实机观察得到的初始响应时间，不代表已实现消除动画结束识别，仍须实机核对慢动画。
- 乱舞按当前策略阶段及所有可达阶段收集视觉指标依赖，只读取确实需要的敌我血量和奥义就绪；条件组、后续阶段转变和已启用奥义前置均计入，普通阶段仍读全量指标。不改变阶段评估或转变规则，不根据当前值裁掉潜在分支。跳过指标使用未知值并记入unchecked_metrics，不复制历史读数。已确认只有普通手数和乱舞状态条件且禁用奥义的阶段，无需血量OCR或奥义识别。
- 策略运行时先评估阶段，再按阶段配置的优先级选择一步动作；只有选择普通连线时才生成当前帧候选路线。
- 奥义和炸弹点击后立即返回截图主循环；下一轮基于新截图继续决策，不增加单独的等待确认步骤。
- 普通连线按住起点500毫秒后连续划完整条路线，松手前只截图一次。当前帧识别到连线菱形就给整场与本阶段手数各加一；起点、终点可以同时有菱形，不要求唯一或落在计划末点。取消逐段截图、确认、回退重滑与连接数量读取。乱舞按下起点后先确认游戏接入，再扫动，不计入普通手数。
- 乱舞每轮从当前帧可信普通饿鬼中预选非保留色起点，并直接读取该点两侧和下部的身体颜色；首个候选局部证据不足时尝试本帧其他候选。同色内优先当前帧颜色余量较大的点：向四个方向分别偏移身体尺寸的8%检查颜色，用通过次数排序；不改变实际起点，不搜索或跟踪移动对象，颜色轮换顺序保持。下一张独立截图只检查预选原点的局部像素，跳过整盘对象检测；连续两次命中同一普通颜色且不是保留色即可起手。局部确认帧使用新帧编号、空对象列表，并明确记录跳过的对象范围；需要的奥义与血量仍使用当前帧识别，炸弹优先级待完整识别帧重新检查。确认后的点、颜色和帧编号一并交给执行器，不再用全盘对象框复核或换点。
- 预选点变成另一非保留色时，将本帧作为同点新颜色的第一次证据；颜色未知、命中保留色或布局改变时重新预选。未知、不可操作、普通状态及动作后清空待确认点。特殊黑色不能作为普通颜色证据；全盘只有保留色时等待。跨帧仅保留待确认点、采样身体尺寸、颜色及布局元数据，不用旧对象限定整盘识别搜索或补回结果。
- 乱舞起点通过按下前的连续两帧同点、同一非保留色确认后，按下即开始完整扫动。不再通过起点选中描边判断是否开始，不增加按下后两张接入截图或渲染等待。起手前仍检查当前乱舞状态、帧归属与保留色；按下前图保留独立副本供诊断，避免后续截图缓冲区覆盖。执行报告以start_selection_check=disabled标明不做选中描边检查；该标记不代表已确认游戏接入。
- 乱舞状态保留原56像素颜色标记，并以同帧倒计时的两位白字、小数点和品红描边作为补充证据；仍要求战斗齿轮存在，并排除胜负及普通可操作状态冲突。补充条件已通过十张现场图（包括0.9秒）及开发集两张正样本、41张负样本回归，适用范围为已核对的720×1280布局。
- 乱舞起手后强制按整个棋盘边界生成密集完整折返，包含上下左右边缘；不查询同色饿鬼位置，不添加身体必经点。扫描间距按截图短边的5%缩放，仅为手势覆盖密度，不表示棋盘行列。折返点之间按普通连线的采样密度插入触点：步长为当前可信身体短边的20%，上限32像素；确认帧对象为空时使用本轮双帧确认携带的身体尺寸，不能退回64像素大步跳跃。尺寸未知的兼容调用最多32像素一步；无效确认尺寸中止并释放。不追加对象识别或描边检查。每遍仍共享400毫秒目标时间表；密集触点会增加指令数量，设备较慢时允许超过目标时间，仍保留全部触点，不能据此保证五次目标或游戏逐个处理所有触摸事件。期望通过提速在一次乱舞内完成约五次独立连线，不设置次数上限，实际次数受乱舞剩余时间、起点确认和补扫影响。首遍后保持按住，从新截图确认乱舞状态，并进行一次轻量颜色像素统计；只在发现明显未连目标色的褪白细长外缘时反向全盘补扫一次，整笔最多两遍。像素统计将区域宽度限制在360以内，不生成饿鬼位置；五张现场图实测中位约1.0至1.2毫秒。没有强阳性时记录未知并释放，不能据此宣称已全部连接。当前仅验证蓝、绿、黄色，红色残留检查返回未知。画面不再确认乱舞、截图或反馈异常、用户停止时结束并释放。
- 实时乱舞不做菱形定位或连线数字OCR，数量缺失与误读均不参与补扫控制。离线数字辅助先按亮白核心和青蓝描边提取数字图，再核对OCR位数与可见部件数；七张实机回归均正确，但不增加运行时识别调用。每遍末尾原图保存在内存，松手后再落盘；乱舞松手后500毫秒等待从实际释放时刻起算，诊断写盘时间计入这半秒。
- 首遍末尾先做残留像素统计；同时检查当前帧局部褪白弧线的形状及附近是否缺少青色描边，避免少量遗漏被全盘比例稀释。不输出同色饿鬼位置，不改变全屏扫动路线。最新三张少量漏连及三种缩放可触发补扫，旧全连对照保持未知；未知不能视为全连。没有强残留证据时直接释放，不再执行原生战斗状态识别。只有确实准备反向补扫时，才重新确认当前帧仍处于乱舞。补扫末尾已没有后续动作，取得诊断截图后立即释放，跳过状态和残留检查。报告通过state_checked、feedback_checked及feedback_skip_reason标明未执行的检查，不能把跳过记为识别成功。当遍400毫秒目标轨迹仍完整执行，不增加途中检查或提前判定全连。
- 实际按下、移动和松手事件统一按整笔起始时刻计时，报告分别记录各遍方向、状态、残留像素证据、耗时和退出原因。预选图写盘移到松手后，减少确认起点至实际按下的画面变化间隔。debug/battle-preview轮换保留最近六轮起手前、每遍按住原图、最后可用按住图及JSON；latest-ranbu-execution.json指向最新一轮。完整派发与残留未知都不代表全部同色饿鬼已经接入，实机收益仍待下一次运行核对。按下提交、等待及后续执行均处于释放保护内；截图及诊断保存异常不阻止尝试释放触点。
- 普通连线比较连续两帧独立识别结果，允许底部至多一只普通四色饿鬼漏检、重现或局部识别抖动，其余对象仍须逐一稳定匹配，并至少保留两个匹配对象；炸弹、障碍物与特殊黑色饿鬼不适用该例外。底部范围按本帧饿鬼身体高度中位数的1.25倍确定，最多占棋盘高度20%，覆盖整个底边，不依赖一、二、三号位箭头检测。触发容差时，仅从当前帧生成上方规划视图，暂时排除身体与底部带相交的饿鬼，并裁剪路线边界以防线段穿入；不补回旧帧对象，不改变每帧独立定位。完全匹配后恢复全盘候选，状态中断或动作后清除许可。诊断记录底部避让边界与放行原因。松手后仍等待1秒再取下一张棋盘图。估计尺寸容纳相邻模板尺度变化及浮点误差，位置容差不变；最近一次稳定拒绝证据另存，不被通过结果覆盖。
- 菱形先匹配彩色外观，当前白色核心附近未命中时以相同阈值复核灰度结构，避免粉色闪动遮蔽标记。整笔未确认时，松手后保存本次唯一截图及同帧识别结果；不额外截图，不用旧坐标补回，不读取连接数量。
- 战斗内部确认胜利或失败后返回 Pipeline；Pipeline 再分别识别胜利结算评级或失败确认画面。两个识别节点均不执行后续点击，识别后的处理流程待定。
- 设备输入和截图识别已接入代码，真实 MuMu/ADB 战斗效果尚未验收；当前视觉路线和触控规则仍须以运行日志及新截图核对。

### 黑色饿鬼的全局优先级（2026-10-22）

用户已确认黑色饿鬼只与黑色连接，连接距离与普通饿鬼相同。存在本帧合法黑色路线时，普通和乱舞阶段都优先于奥义、炸弹、普通四色路线及四色全屏扫动。仅出现孤立黑色、距离超限或缺少可信触点时，继续使用原策略。黑色不加入普通四色的策略颜色列表，也不与其他颜色混连。

黑色触点从本帧可见模板锚点生成并排除炸弹覆盖；候选路线沿用既有同色几何检查，有限搜索先处理黑色分量。普通状态仍需连续两帧稳定；底部容差区域内无法安全连接黑色时继续等待，不能改选普通颜色。乱舞从当前帧独立识别结果直接检查黑黑路线，不添加描边判断或新的按住截图。执行前核对本帧对象、识别质量及可信落点，不接受脱离当前对象的旧坐标。

黑色手势的采样步长随本帧身体尺寸缩放。普通状态确认连接后计入普通连线手数，乱舞期间不计入普通手数。松手后的响应等待保持普通一秒、乱舞半秒。


### 普通棋盘局部识别差异避让（2026-10-22）

20:10的运行中，全盘对象数在46至50间跳变，普通连线等待16秒。末尾保存的相邻结果中，48个对象均能匹配，仅贝壳和绿色饿鬼缺失，支持局部漏检影响全盘等待；没有足够原图证明整段等待都由相同对象引起。因此在原有底部单只容差之外，增加局部例外：相邻独立结果至少90%的对象逐一匹配，每帧未匹配对象最多4个；至少6个可信匹配对象，横向和纵向跨度都覆盖当前棋盘至少一半。几何逐项比较仍保留，未用总数或平均位置代替匹配。上述比例和数量是有限工程边界，不是新增游戏规则。

局部例外只接受普通四色饿鬼和已登记障碍物的检测差异。黑色或炸弹出现、消失、分类变化，明显的局部位移，主体移动、差异过多、稳定对象集中一角，以及无效布局或对象几何，仍不通过该例外。原有底部单只容差继续生效。

差异前后身体框加上随尺寸变化的余量，形成当前规划的暂时避让区。旧位置只用于状态比较和避让；所有识别仍逐帧独立全范围执行，不以旧框限制搜索、不补回旧对象。规划视图只保留当前帧匹配对象，在BoardResult.route_exclusion_regions中明确记录避让区。候选点、实际取整触点与每一段连线都要避开这些区域；端点在区外而中间线段穿过或贴边也会被拒绝。预演图用橙色矩形显示避让区，原始观测保持不变。

黑色最高优先级保留。若黑色路线在暂时避让区域内无法安全连接，继续等待，不能让奥义、炸弹或彩色路线抢先。完整匹配后恢复全盘规划，动作或状态中断后重新取得稳定证据。本次复用已有识别结果，不增加截图、OCR或模板识别次数，不改变松手后响应等待。
